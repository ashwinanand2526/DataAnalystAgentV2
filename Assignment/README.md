# Session 5 Assignment: Pydantic LLM Gateway & MCP Agent

This repository contains the complete implementation for the **Session 5 Assignment**, which integrates a **Pydantic-based LLM Gateway V2** with an **MCP-based Data Analyst Agent**. The agent interacts with an MCP server to solve data analysis tasks, write to a sandbox, and render dynamic interactive dashboards via the Prefab UI framework.

---

## 📂 Project Structure

All files required to run this project are self-contained within the `Assignment` directory:

```text
Assignment/
├── llm_gatewayV2/              # The LLM Gateway V2 backend
│   ├── main.py                 # FastAPI application and route handlers
│   ├── router.py               # Gateway routing logic (latency/RPM-based load balancing)
│   ├── providers.py            # Provider adapters (Gemini, Groq, Cerebras, OpenRouter, NVIDIA, GitHub)
│   ├── db.py                   # SQLite DB logger for tracking calls, cache tokens, and reasoning
│   ├── cache.py                # Gemini-explicit SHA-256 prompt cache module
│   ├── schemas.py              # Pydantic v2 schemas for API requests & responses
│   ├── client.py               # Internal httpx client wrapper for the Gateway
│   ├── gateway_v2.db           # SQLite database for storing API call logs
│   ├── requirements.txt        # Gateway-specific dependencies
│   ├── static/                 # Frontend assets for the Gateway Dashboard
│   │   ├── dashboard.html      # Gateway metrics dashboard
│   │   └── help.html           # Gateway help documentation
│   └── tests/                  # Verification suite
│       └── test_all_providers.py
├── sandbox/                    # Workspace directory for agent operations
│   ├── dashboard_app.py        # Dynamic Prefab UI dashboard script generated by the agent
│   ├── gateway_log.txt         # LLM Gateway background process output logs
│   ├── prefab.log              # Prefab dashboard server execution logs
│   └── prompt_log.txt          # Active logs of prompts sent to the LLM
├── .env                        # Environment configurations containing API keys & model settings
├── agent.py                    # Main interactive agent loop (Plan -> Act -> Verify)
├── client.py                   # Local LLM Gateway V2 client wrapper used by the agent
├── mcp_server.py               # FastMCP Server registering data and UI rendering tools
├── schemas.py                  # Local schema structures for type validation
└── requirements.txt            # Unified dependencies file for the entire assignment
```

---

## 🛠️ How It Works

1. **Interactive Agent Loop (`agent.py`)**:
   - Serves as the main loop waiting for user queries.
   - Sends prompts to the LLM Gateway V2 and processes responses.
   - Orchestrates tool calls against the local MCP server when requested by the model.

2. **Assignment MCP Server (`mcp_server.py`)**:
   - Exposes tools to fetch online data (Wikipedia search/URL extraction), read/write to the local sandbox, and render the **Prefab UI** dashboard.
   - Generates the live Prefab app in `sandbox/dashboard_app.py` and hosts it on port `5175`.

3. **LLM Gateway V2 (`llm_gatewayV2/`)**:
   - Translates requests (messages, system instructions, tools, schemas, and reasoning budgets) into provider-specific payloads.
   - Implements capability-aware failover routing, rate limiting backoffs, and auto-corrective structured output retries.
   - Tracks metrics inside a local SQLite database (`gateway_v2.db`).

## 🚀 Installation Guide

### Prerequisites
* **Python 3.13** or higher.
* [**uv**](https://github.com/astral-sh/uv) (recommended) or standard `pip` for package management.

### Setup Steps

1. **Clone/Navigate to the workspace**:
   ```bash
   cd d:/TSAI/Session5_Pyd_Gateway/Assignment
   ```

2. **Configure your API keys**:
   The `.env` file containing the model provider API keys and default routing configurations is located directly in the `Assignment` folder. Open it and verify or configure your keys:
   ```env
   GEMINI_API_KEY=your-gemini-key
   GROQ_API_KEY=your-groq-key
   CEREBRAS_API_KEY=your-cerebras-key
   OPEN_ROUTER_API_KEY=your-open-router-key
   NVIDIA_API_KEY=your-nvidia-key
   GITHUB_ACCESS_TOKEN=your-github-token
   
   # Gateway settings
   LLM_ORDER=gemini,groq,cerebras,openrouter,github,nvidia
   GATEWAY_V2_PORT=8100
   ```

3. **Install Dependencies**:
   Create a virtual environment and install the dependencies from the local `requirements.txt`:
   
   **Using `uv` (Recommended)**:
   ```bash
   # Create a virtual environment and install dependencies
   uv venv
   # Activate environment
   .venv\Scripts\activate   # On Windows
   source .venv/bin/activate # On Unix/macOS
   # Sync packages
   uv pip install -r requirements.txt
   ```
   
   **Using standard `pip`**:
   ```bash
   # Create a virtual environment
   python -m venv .venv
   # Activate environment
   .venv\Scripts\activate   # On Windows
   source .venv/bin/activate # On Unix/macOS
   # Install packages
   pip install -r requirements.txt
   ```

## 🏃 Running the Project

1. **Start the Interactive Agent**:
   With your virtual environment activated, run the main agent:
   ```bash
   python agent.py
   ```

2. **Under the hood**:
   - `agent.py` checks if the **LLM Gateway V2** is running on port `8100`.
   - If not running, it automatically spawns `llm_gatewayV2/main.py` in the background and saves logs to `sandbox/gateway_log.txt`.
   - It starts the MCP server using `sys.executable` and connects to it.
   - It prompts you for a task in the terminal.

3. **Interact with the Agent**:
   Give the agent a task (e.g., *"Find the highest grossing movies of 2025 and render a dashboard showing them"*).
   - The agent will search online.
   - It will save findings as CSV/JSON in the sandbox.
   - It will generate a dynamic dashboard and serve it on `http://127.0.0.1:5175`.
   - It will open your web browser automatically to show you the live dashboard!

## 📊 Verification & Diagnostics

While the agent is running:

* **Gateway Web Dashboard**: Open `http://localhost:8100` in your browser to view a live status dashboard of all providers, RPM, RPD, cache hits, and recent calls.
* **Provider Capabilities**: Check which capabilities (tools, caching, reasoning, structured output) are active for each model by hitting:
  ```bash
  curl http://localhost:8100/v1/capabilities
  ```
* **Status Endpoint**: Retrieve active health status and usage counts:
  ```bash
  curl http://localhost:8100/v1/status
  ```
* **Run Gateway Tests**: Execute the internal test suite to check provider status and capability compliance:
  ```bash
  python llm_gatewayV2/tests/test_all_providers.py
  ```
